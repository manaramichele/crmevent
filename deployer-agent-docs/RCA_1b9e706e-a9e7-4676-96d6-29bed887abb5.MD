## 3. Precise exception / cause of the remaining 502
This is an APP-level HTTP 502, not a Cloudflare origin failure and not an objstore timeout. Correlated log sequence on each pod:
```

```
Code path (server.py:5069–5133, `social_post_publish`):
- `instagram_utils.create_media(...)` → Instagram `/media` returns 200 (container created OK).
- `instagram_utils.publish_media(...)` → Instagram `/media_publish` returns **400 Bad Request** → raises.
- Except block (server.py:5130–5133) sets post status=`error`, stores `last_publish_error`, and `raise HTTPException(status_code=502, detail="Pubblicazione Instagram fallita: ...")`.
=> The 502 is the backend deliberately re-mapping an upstream Instagram Graph API **400** into a **502**. Root cause is Instagram-side rejection of the publish (media container created but publish rejected — typically image/container readiness, aspect ratio, or account/permission on Meta's side), NOT object storage.

Object-storage path check: no `requests.exceptions.Timeout`, no `ConnectionError`, no non-200 from `/objstore/.../objects/{path}` in any log line. get_object served the creative bytes successfully (200s above).
