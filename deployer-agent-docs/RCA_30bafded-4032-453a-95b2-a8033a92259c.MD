# RCA — Risoluzione di STRIPE_MODE in produzione (manage-events-12)

## Richiesta (READ-ONLY)
Capire come `STRIPE_MODE` viene risolto a runtime in produzione e se per passare a `STRIPE_MODE=live` basta modificare `backend/.env` committato + redeploy, oppure serve aggiornare il secret dalla UI.

## Evidenze (da `list_secrets` sul run attivo 30bafded-4032-453a-95b2-a8033a92259c)
- Esiste un secret con nome esatto **`STRIPE_MODE`**: `is_empty=false`, `matches_expected=true` rispetto alla stringa `"test"`.
- `STRIPE_MODE` è una **Custom Key** (secret applicativo dell'utente): è una config della sua integrazione Stripe, non una delle chiavi di sistema rigenerate dalla piattaforma. Nello store sono presenti anche altre custom key Stripe dell'app (`STRIPE_SECRET_KEY`, `STRIPE_PUBLISHABLE_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_ACCOUNT_ID`, `CRMEVENT_STRIPE_*_LIVE`).

## Risposte
1. **Sì** — esiste un secret denominato esattamente `STRIPE_MODE`, categoria **Custom Key**, valore non vuoto.
2. **Sì** — il valore corrente corrisponde esattamente a `"test"` (`matches_expected=true`).
3. **Vince il secret nello store, non il `backend/.env` committato.** Modello secret: per ogni deploy successivo al primo, le Custom Key vengono riportate dal run di PRODUZIONE precedente; il `.env` del preview può solo AGGIUNGERE chiavi nuove, non sovrascrive una chiave già presente/personalizzata in prod. Poiché `STRIPE_MODE` esiste già in prod con valore `test`, modificare `backend/.env` a `live` + redeploy **NON** lo cambierà: il backend continuerebbe a leggere `test` dal secret.

## Conclusione
Per attivare `STRIPE_MODE=live` in produzione NON è sufficiente modificare `backend/.env` committato. L'utente deve aggiornare il secret **`STRIPE_MODE`** in Deployment Panel → Secrets impostandolo a `live`, poi effettuare il redeploy. (Nota: non ho modificato nulla — operazione read-only.)
