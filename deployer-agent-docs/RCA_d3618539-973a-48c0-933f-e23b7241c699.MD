## TL;DR (answer to "why does selecting Trento show Pisa people?")
In THIS Emergent deployment it **cannot**, and the DB behind it does **not** contain a Trento org. Two independent facts explain the contradiction:

1. **crmevent.it is NOT currently served by this deployment.** Live DNS A-record check: `crmevent.it` and `www.crmevent.it` → "A records do not point to expected IPs". The site the Super Admin is actually using is hosted elsewhere (the repo contains `crmevent-backend-aruba.tar.gz`, `crmevent-frontend-aruba.tar.gz`, `export-aruba/` — i.e. a self-hosted/Aruba export exists). That other environment has its own database and possibly older code, and is **outside the reach of these tools**.
2. **The deployed code on this Emergent backend matches the current repo** and makes the reported behavior impossible (see §4). So the Trento→Pisa linkage lives in the OTHER environment's DB, not here.

The previous RCA (RCA_d3618539) was therefore correct about the Emergent DB — it just isn't the DB that is currently answering crmevent.it.
