## Root cause
Google's token endpoint returns `400 invalid_grant / "Missing code verifier."` This is a **PKCE mismatch in the app's own OAuth flow**: the authorization (consent) request sent a `code_challenge` (PKCE enabled), so Google requires the matching `code_verifier` on the token-exchange POST — but the backend's token exchange did not include `code_verifier`. It is not a Test-User / consent problem (consent succeeded, a valid code was returned) and not a client-credential problem (would be `invalid_client`/`unauthorized_client`) and not `redirect_uri_mismatch`.

## Suggested fix (not applied)
Code fix (E1): make the OAuth authorization and token-exchange consistent on PKCE — either (a) send the stored `code_verifier` in the token-exchange request that matches the `code_challenge` used at authorization, or (b) drop PKCE entirely (omit `code_challenge` at authorize) if the flow is not intended to use it. This is a source change in the backend calendar OAuth handler; redeploy after.
