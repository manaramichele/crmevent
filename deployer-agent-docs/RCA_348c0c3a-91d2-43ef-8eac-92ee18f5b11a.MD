## Interpretation for the removal question
- With EMAIL_PROVIDER=brevo and BREVO_API_KEY populated, send_email() provider order is [brevo, resend(fallback), managed]. A successful Brevo send returns before Resend is touched — consistent with the user's successful real test.
- RESEND_API_KEY currently functions ONLY as the fallback. It is still present in production.
- Removing RESEND_API_KEY is safe strictly in the sense that the happy path (Brevo success) never calls it. The trade-off: if a Brevo send ever fails, the fallback chain would skip Resend and drop to `managed`. This is a user decision + action in Deployment Panel -> Secrets.
